【阶段任务】

本阶段只负责定位 Analysis 阶段已有动作的时间边界，不重新识别或修改动作序列。

时间边界必须由视频中的直接视觉证据支持。任务指令、Scene 阶段结果、动作词表和 Analysis 阶段结果只能作为辅助上下文，不能代替视频证据。

【独立时间线要求】

- 必须保持 Analysis 阶段的 executor_timelines 分组结构。
- 每个执行主体的动作时间边界应根据该执行主体自身的视觉证据独立定位。
- 不得预先假设不同执行主体的动作时间一定互斥。
- 不得预先假设不同执行主体的动作时间一定重叠。
- 如果视频显示不同执行主体依次操作，则各自动作区间可以完全不重叠。
- 如果视频显示不同执行主体同时操作，则应保留真实的时间重叠。
- 不同执行主体的动作区间可以呈现以下任一关系：
  - 完全不重叠；
  - 部分重叠；
  - 完全重叠；
  - 一个动作区间包含另一个动作区间。
- 不得为了形成整齐、连续的时间切片而消除真实重叠。
- 不得为了体现多机械臂并行而人为制造不存在的时间重叠。
- 一个执行主体开始动作，不能自动作为另一个执行主体结束动作的依据。
- 某个时间段已经被一个动作使用，不影响其他动作在视频证据支持时使用相同时间段。
- 不要求所有动作连续覆盖完整视频，动作之间可以存在等待、停顿或未标注区间。
- 不得新增 executor = "both" 的动作。
- 本阶段不判断双臂协作、交接、共同搬运或其他多执行主体关系。

【字段复用要求】

以下字段必须完全复用 Analysis 阶段的值，不得修改：

- executor；
- step_id；
- executor_step_index；
- action；
- object；
- target；
- temporal_type；
- executor_object_relation。

必须按照 Analysis 阶段原有的执行主体分组和动作排列顺序输出。

其中：

- step_id 是整个视频内唯一的动作引用标识；
- step_id 不表示不同执行主体之间严格的全局时间顺序；
- executor_step_index 只表示当前执行主体内部的动作顺序；
- 不得因为某个 step_id 较大，就强制其在所有较小 step_id 的动作结束后开始。

【时间轴要求】

- start_time 和 end_time 使用相对于原始视频起点的秒数。
- 如果输入帧不包含原始视频时间戳，则时间值必须使用数值，不使用“00:01.25”等字符串格式。
- 如果输入帧包含原始视频时间戳，应优先使用该时间戳格式。
- 如果视频经过抽帧，应使用采样帧对应的原始视频时间戳。
- 不得根据抽帧后的视频长度重新计算时间。
- 不得根据多帧拼图中的排列位置推断时间顺序。
- 不得根据多视角拼图中的上下左右位置推断时间顺序。
- 多视角输入应统一使用同一条原始视频时间轴。
- start_time 和 end_time 不得超出视频有效时长。
- 不得给出高于输入时间采样精度的虚假精度。
- 当采样间隔较大时，使用最接近且具有视觉证据支持的时间，并降低 confidence。
- 无法可靠判断某个边界时，可以将该边界填写为 null，并在 sequence_issues 或 uncertainties 中说明原因。

【时间边界基本定义】

start_time 表示当前动作自身首次出现明确、持续且符合该动作语义的开始迹象。

end_time 表示当前动作自身的目标状态已经形成、操作过程已经完成，或者持续状态已经解除。

每个动作必须依据其自身视觉证据独立判断边界，不得直接使用：

- 上一个动作的 end_time 作为当前动作的 start_time；
- 下一个动作的 start_time 作为当前动作的 end_time；
- 另一个执行主体的动作边界；
- step_id 或 executor_step_index 的排列位置；
- 标准任务流程中的预期时间。

【根据 temporal_type 定位】

必须沿用 Analysis 阶段给出的 temporal_type，不得静默修改。

一、当 temporal_type 为 "状态转换型" 时：

- start_time 表示原有状态开始发生变化的时刻；
- end_time 表示目标状态已经稳定形成的时刻；
- 状态转换型动作仍具有实际持续时间；
- 不得将其默认处理为零时长事件；
- 当两个边界均可判断时，应满足 start_time < end_time。

例如：

抓取：
- 开始：夹爪开始闭合、接触物体或建立抓取关系；
- 结束：物体已经被稳定持有，并能够跟随执行主体运动。

放置：
- 开始：被持有物体开始接近或接触最终支撑位置；
- 结束：物体已经获得稳定支撑，不再依赖执行主体承托。

释放：
- 开始：夹爪开始打开或开始解除控制关系；
- 结束：物体不再被执行主体持有，也不再跟随执行主体运动。

二、当 temporal_type 为 "持续过程型" 时：

- start_time 表示目的性运动或操作过程明确开始的时刻；
- end_time 表示该过程完成、停止，或者动作意图转变为另一个独立动作的时刻。

例如：

接近：
- 开始：执行主体开始持续向目标物体或目标区域运动；
- 结束：到达目标附近，并开始对准、接触或抓取。

对准：
- 开始：末端、工具或物体开始针对目标位置调整位置或姿态；
- 结束：达到能够执行后续插入、放置或其他操作的对准状态。

提起：
- 开始：被持有物体开始脱离原支撑面；
- 结束：物体已经明显脱离支撑面并达到稳定提起状态。

搬运：
- 开始：被持有物体开始从原区域向目标区域转移；
- 结束：物体到达目标操作区域，并开始降低、对准或放置。

推动或拉动：
- 开始：形成有效接触，并且物体开始产生对应位移；
- 结束：物体停止对应位移，或者有效接触关系解除。

旋转或翻转：
- 开始：物体开始发生有目的的姿态变化；
- 结束：物体达到新的稳定姿态。

插入：
- 开始：部件开始进入目标开口、插槽或配合结构；
- 结束：部件达到目标深度，或者插入过程明显完成。

拔出：
- 开始：部件开始从目标结构中退出；
- 结束：部件完全脱离目标结构，或者退出过程明显完成。

三、当 temporal_type 为 "持续状态型" 时：

- start_time 表示该状态已经建立，并开始稳定维持的时刻；
- end_time 表示该状态被解除、失效或不再维持的时刻；
- 必须尽可能覆盖该状态实际持续存在的完整区间；
- 不能只标注状态建立时的一小段时间；
- 在视频证据支持时，可以与其他动作发生时间重叠；
- 不得默认所有持续状态型动作都必须与其他动作重叠。

例如：

夹持：
- 开始：执行主体已经建立稳定持有关系；
- 结束：夹持关系解除，或者物体不再受该执行主体控制。

固定：
- 开始：执行主体开始稳定限制物体的位置或姿态；
- 结束：执行主体解除限制，或者物体不再由该主体维持稳定。

支撑：
- 开始：执行主体开始承担物体的承托或支撑作用；
- 结束：支撑关系解除，或者支撑作用转移到环境结构或其他执行主体。

等待：
- 开始：执行主体停止当前目的性操作并进入等待状态；
- 结束：执行主体开始新的目的性操作，或者等待条件结束。

四、当 temporal_type 为 "未知" 时：

- 结合 action、state_change、evidence、executor_object_relation 和视频内容保守定位；
- 不得擅自将 temporal_type 修改为其他类型；
- 如果能够判断动作实际发生区间，可以正常输出 start_time 和 end_time；
- 如果无法确定应按状态转换、持续过程还是持续状态定位，可以将相关边界填写为 null；
- 应在 sequence_issues 中记录“时间类型可能不准确”或“无法可靠定位”。

【同一执行主体内部的时间关系】

同一个执行主体的动作不一定全部互斥。

在视频证据支持时，持续状态型动作可以与持续过程型动作重叠，例如：

- 夹持与提起；
- 夹持与搬运；
- 夹持与旋转；
- 支撑与调整；
- 固定与其他仍维持固定关系的操作。

例如：

- 抓取：2.0 秒至 2.6 秒；
- 夹持：2.6 秒至 7.0 秒；
- 提起：2.6 秒至 3.4 秒；
- 搬运：3.4 秒至 5.8 秒；
- 放置：5.8 秒至 6.4 秒；
- 释放：6.4 秒至 7.0 秒。

其中，“夹持”可以覆盖提起、搬运和放置过程，因为夹持表示持续存在的控制关系。

但是，以下表示相反状态或不同操作阶段的动作，通常不应在缺少视频证据时出现明显重叠：

- 抓取与释放；
- 接近与撤回；
- 插入与拔出；
- 打开与关闭。

是否允许重叠必须根据动作语义和视频证据判断，不得机械套用。

【不同执行主体之间的时间关系】

- 不同 executor 的动作必须分别独立定位。
- 不同执行主体操作不同物体时，动作可以重叠，也可以不重叠。
- 不同执行主体操作同一物体时，动作同样可以重叠，也可以不重叠。
- 如果一个机械臂先接触物体，另一个机械臂后接触物体，应分别使用各自实际接触或控制关系建立的时间。
- 第一个机械臂的动作开始时间不得作为第二个机械臂的动作开始时间。
- 第二个机械臂开始动作，不得自动结束第一个机械臂仍在持续的动作。
- 如果视频显示两个机械臂依次操作，应保留互不重叠的真实区间。
- 如果视频显示两个机械臂同时操作，应保留真实的重叠区间。
- 本阶段不判断时间重叠是否构成协作、交接或共同操作关系。

以下示例只用于说明允许的时间关系，不表示所有双臂视频都必须存在重叠。

情况一，不同执行主体依次操作：

- 左臂抓取物体：1.0 秒至 2.0 秒；
- 右臂抓取物体：3.0 秒至 4.0 秒。

两个动作完全不重叠。

情况二，不同执行主体并行操作：

- 左臂固定物体：2.0 秒至 8.0 秒；
- 右臂接近部件：3.0 秒至 4.0 秒；
- 右臂抓取部件：4.0 秒至 4.8 秒；
- 右臂插入部件：5.0 秒至 7.0 秒。

左臂的固定动作与右臂的多个动作存在真实重叠。

【动作开始边界证据】

判断 start_time 时，应优先寻找：

- 执行主体开始持续朝当前目标运动；
- 夹爪开始打开或闭合；
- 执行主体开始与物体接触；
- 物体开始跟随执行主体运动；
- 物体开始脱离支撑面；
- 物体开始改变位置、姿态或包含关系；
- 部件开始进入或退出目标结构；
- 夹持、固定或支撑关系开始稳定建立。

不要将以下内容计入当前动作的开始时间：

- 与当前动作无关的等待；
- 短暂抖动；
- 无明确操作目的的姿态变化；
- 上一个动作的尾部；
- 另一个执行主体的动作开始时间。

【动作结束边界证据】

判断 end_time 时，应优先寻找：

- 当前动作的目标状态已经稳定形成；
- 夹爪完成闭合或打开；
- 物体建立或解除稳定持有关系；
- 物体完全脱离原支撑面；
- 物体到达目标操作区域；
- 物体获得新的稳定支撑；
- 物体完成预期姿态变化；
- 插入、拔出、打开或关闭过程完成；
- 推动、拉动、旋转或搬运过程停止；
- 固定、夹持或支撑关系解除；
- 当前执行主体停止当前操作意图，并转入另一独立动作。

不得因为以下情况提前结束当前动作：

- 另一个执行主体开始动作；
- 后一个 step_id 出现；
- 另一个物体开始运动；
- 标准任务流程预期进入下一步。

【视觉证据要求】

每个动作必须分别提供：

- start_boundary_evidence：支持动作开始边界的直接视觉证据；
- end_boundary_evidence：支持动作结束边界的直接视觉证据。

视觉证据应优先描述：

- 机械臂运动的开始或停止；
- 夹爪开合；
- 接触关系变化；
- 物体是否跟随执行主体；
- 物体是否脱离或获得支撑；
- 物体位置、姿态或包含关系变化；
- 部件进入、退出或机构状态变化；
- 夹持、固定或支撑状态是否仍然持续。

不得将以下内容作为视觉证据：

- 任务指令；
- 动作词表；
- 标准任务流程；
- 未经视频确认的力、重量、控制信号或内部状态。

【多视角要求】

- 综合所有可用视角定位动作时间。
- 同一个动作在不同视角中只输出一组 start_time 和 end_time。
- Scene 阶段提供的 best_observation_views 只作为优先观察建议，不能忽略其他视角的有效证据。
- 开始边界和结束边界可以分别依据不同视角判断。
- 当一个视角发生遮挡时，应结合其他视角中的夹爪状态、物体位移、接触关系和支撑关系。
- 不得根据多视角拼图中的画面排列位置推断时间顺序。
- 单视角输入时，直接依据唯一视角定位，不虚构其他视角证据。
- 如果不同视角未同步或时间信息发生冲突，应降低 confidence，并记录到 uncertainties。

【序列问题】

如果视频证据表明 Analysis 阶段可能存在以下问题：

- 动作遗漏；
- 动作重复；
- 粒度错误；
- 执行主体内部顺序错误；
- 动作名称错误；
- temporal_type 错误；
- executor_object_relation 错误；
- 动作无法可靠定位；

则：

- 不得直接修改原动作；
- 不得新增或删除 step_id；
- 不得改变执行主体分组；
- 不得修改 temporal_type；
- 不得修改 executor_object_relation；
- 将问题记录到 sequence_issues；
- 使用相关动作的 step_id；
- 如果问题涉及多个动作，可以填写多个 step_id；
- 如果无法关联到现有动作，step_ids 返回空数组。

【输出语言与格式】

- JSON Key、executor_id、object_id 和视角名称可以使用英文。
- action 必须完全复用 Analysis 阶段的值。
- 其他自然语言内容必须使用中文。
- start_time 和 end_time 使用秒数值或 null。
- confidence 使用 0 到 1 之间的小数。
- 没有序列问题时，sequence_issues 返回空数组。
- 没有明显不确定性时，uncertainties 返回空数组。
- 只输出合法 JSON，不输出 Markdown、解释或其他额外内容。

严格返回以下 JSON：

{
  "timed_executor_timelines": [
    {
      "executor": "完全复用 Analysis 阶段的 executor",
      "actions": [
        {
          "step_id": 1,
          "executor_step_index": 1,

          "object": "完全复用 Analysis 阶段的 object 或 null",
          "target": "完全复用 Analysis 阶段的 target 或 null",
          "temporal_type": "完全复用 Analysis 阶段的 temporal_type",
          "executor_object_relation": "完全复用 Analysis 阶段的 executor_object_relation",

          "end_time": 1.0,
          "start_boundary_evidence": "用中文描述支持动作开始边界的直接视觉证据",

          "boundary_views": [
            "用于判断开始边界或结束边界的真实输入视角名称"
          ],
          "confidence": 0.0
        }
      ]
    }
  ],

  "sequence_issues": [
    {
      "step_ids": [1],
      "issue_type": "可能遗漏动作 | 可能重复动作 | 动作可能需要拆分 | 动作可能需要合并 | 执行主体内部顺序可能有误 | 动作名称可能不准确 | 时间类型可能不准确 | 交互关系可能不准确 | 无法可靠定位 | 其他",
      "description": "用中文说明视频证据与 Analysis 阶段结果之间的问题"
    }
  ],

  "uncertainties": [
    "用中文说明可能影响时间定位的遮挡、采样不足、时间戳缺失、视角不同步、边界模糊或动作持续状态不清晰等问题"
  ]
}

输出前检查：

1. timed_executor_timelines 是否覆盖 Analysis 阶段的全部 executor；
2. 每个 executor 是否保留 Analysis 阶段的全部动作；
3. 是否保持了 Analysis 阶段原有的执行主体分组和动作顺序；
4. step_id 是否完整且未被重新编号；
5. executor_step_index 是否与 Analysis 阶段完全一致；
6. action、object、target、temporal_type 和 executor_object_relation 是否完全复用；
7. 是否为每个执行主体的每个动作独立定位时间；
8. 是否避免预设不同执行主体的动作一定互斥；
9. 是否避免预设不同执行主体的动作一定重叠；
10. 视频中真实依次发生的动作是否保持不重叠；
11. 视频中真实并行发生的动作是否保留重叠；
12. 是否错误地因为另一个执行主体开始动作而结束当前动作；
13. 同一执行主体的持续状态型动作是否在证据支持时保留完整持续区间；
14. 是否根据 temporal_type 使用对应的边界判断规则；
15. 状态转换型动作是否未被错误处理为零时长事件；
16. 是否使用原始视频时间轴；
17. 每个非 null 时间是否位于视频有效时长范围内；
18. 当 start_time 和 end_time 均非 null 时，是否满足 start_time < end_time；
19. 是否根据动作自身视觉证据定位边界，而不是按照动作数量平均分配时间；
20. 是否错误地根据拼图位置或抽帧后的视频长度计算时间；
21. 是否将不同视角中的同一个动作重复输出；
22. 是否新增了 executor = "both" 的动作；
23. 是否在发现上游问题时只记录 sequence_issues，而没有修改原动作；
24. boundary_views 是否只包含真实输入的视角名称；
25. 输出是否为合法 JSON，且不包含 Markdown 或额外解释。
